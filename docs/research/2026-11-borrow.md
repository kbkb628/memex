## 结论先说

**四件事我们已经在做，不要重复投资。** 包括压缩——pi 默认就开着，官方示例一行都没配。

**五件事值得吸收，其中一件是 bug 级。** 最好的一条不是从别的产品抄的，是从官方笔记里捡回来的。

**上一轮我给错了一条建议**：「抄 worker-personal-agent 的 compact 来解决会话只增不减」是错的。压缩只管上下文，不管存储；而且 pi 根本没有删除会话的接口。下面第三节单独说。

## 一、已经在做的，不要再做

| 能力 | 我们现在的做法 | 对照 |
|---|---|---|
| 崩溃/驱逐后接着跑 | `patrol` + `harness.retry({session})` + `pending()` | coil 的 "Kill and resume" 测的是同一件事 |
| 重复提交只算一次 | `operationId` 当幂等键，落回原会话 | coil 用 `Idempotency-Key` 头，同一思路 |
| 工具输出截断 | `outputLimits: { maxBytes: 60_000, maxLines: 1_500 }` | pi 自带 `truncate`（2000 行 / 50KB，不产生半行） |
| 上下文压缩 | **没配，用默认** | pi 默认 `enabled:true, reserve:16384, keepRecent:20000, background:32768`；官方示例原文写着 "The example sets no `CompactionPolicy` or hooks of its own." |

最后一行要特别记一下。`node_modules/@earendil-works/pi-durable/dist/harness/agent.js` 里 `DEFAULT_COMPACTION_POLICY` 是开着的，所以「上下文会顶到上限」这个担心在我们这里不成立——真正的限制是模型窗口本身，不是我们没配压缩。

## 二、值得吸收的五条

按性价比排序。每条给「对方怎么做 / 我们落在哪 / 代价」。

### 1. 工具没接中止信号（bug 级，3 行）

**来源**：`cloudflare/agents` 的 `NOTES.md`，原文：

> `conversation.abort()` resolves only once the conversation is idle. A tool that ignores `context.abortSignal` hangs it.

**我们现在的样子**：`src/tools.ts:51` 是 `async execute(args)`，只用了 `AbortSignal.timeout(15_000)`。工具签名的第三个参数 `context` 被丢掉了，而 `Context.abortSignal` 是 chord 明确提供的（`dist/context/index.d.ts:10`）。

**后果**：一次 abort 要等到 fetch 自己超时（最多 15 秒）才生效。现在没有暴露 abort 接口，所以还没炸；一旦加「取消这条任务」，它就是那个"点了取消没反应"的来源。

**落点**：

```ts
async execute(args, _api, context) {
  const signal = context.abortSignal
    ? AbortSignal.any([context.abortSignal, AbortSignal.timeout(TIMEOUT_MS)])
    : AbortSignal.timeout(TIMEOUT_MS);
  // ... fetch(target, { signal, ... })
}
```

**代价**：三行。`compatibility_date` 是 `2026-11-01`，`AbortSignal.any` 可用，不需要 chord 的 `withAbortSignal` 兜底。

**优先级：现在就做。**

### 2. 预算从「次数」升级成「花费」

**来源**：`pi-durable` 的 `Harness.usage()` → `UsageState`，按 `provider/modelId` 分桶，工具的花费单独进 `tools`；coil 用它在侧栏显示每人花了多少美元。

**我们现在的样子**：`budget:${day}` 是个整数，每天 20 次。但一次任务读三页网页和一次只回一句话，token 差二十倍。这个闸门现在拦的是"次数"，不是"成本"。

**落点**：`/status` 多一个 `spend` 字段，闸门改成「次数 或 token」两个条件，任一超了就不提交。`this.harness.pi()` 能拿到底层 `Harness`。

**代价**：一次 `usage()` 调用 + 一个字段。**不建议**现在就把闸门换成纯 token——次数是硬的，token 是软的（重试会重复计）。

**优先级：高。** 它让「今天用了 6/20 次」变成「今天 6 次，4.2 万 token」，后者才是真正的成本。

**已做（2026-11-06）**，但做的时候发现原文这条说法不准确，两处修正：

- **`usage()` 给的是累计，不是今天。** 它把每条会话的用量文档各读一遍加总，只增不减；要按天拆必须每天存快照做差。所以 UI 上写的是「累计 13.6 万 token」，和「今天 17/20 次」并排放、各自标清口径。宁可少说一句，也不编一个「今日 token」。
- **它是全表扫描，不能挂在每分钟轮询的路径上。** 页面每 60 秒拉一次 `/status`，不缓存的话一次刷新就是几百次存储读，而且随会话数增长。加了六十秒缓存 + `?spend=fresh` 强制重算。
- **闸门没换。** 仍然按次数拦，token 只显示不拦——理由同上（重试会重复计），而且 deepseek-flash 一天二十次也就几厘钱，现在换闸门是拿成本换复杂度。

验证：`node scripts/receipt.mjs spend`，13/13，见 [receipts/spend.json](../../receipts/spend.json)。

### 3. 回执升级成可提交的凭证

**来源**：coil 的 `receipts/live-e2e.json`。结构是：

```
kind / observed / when / deploy{url,runtime,model} / driver / thread
steps[]      { step, status, ms, body }
transcript[] { role, text }
execs[]      { argv, exitCode, bytes, sha256 }
notes[]      ["第一次尝试是驱动脚本的 bug，不算进这份凭证"]
```

注意最后那个 `notes` —— 它主动声明"哪一段不算数"。这比任何"已验证"的形容词都可信。

**我们现在的样子**：README 里「验到哪儿了」是一张表，文字描述，没有可复现的东西。

**落点**：`receipts/break-resume.json`、`receipts/idempotent.json`，用同一个脚本跑出来，字段照抄。README 那张表改成链接。

**代价**：写一个 `scripts/receipt.mjs`，对本地 `wrangler dev` 发请求、记录、落盘。半天。

**优先级：高。** 这是我们唯一真正展示的东西，现在只有形容词。

### 4. 回执记「开始」和「结束」，不只记「提交」

**来源**：coil `ledger.ts` 的 `coil_turns` 表，用 `done INTEGER NOT NULL DEFAULT 0` 标记未完成的轮次，`openTurn()` 找出"上一轮没结束"，`finishTurn()` 补上 `stat/diff/tools/ended`。

**我们现在的样子**：`op:{id}` 只有 `{ id, text, at, session }`。`at` 是提交时间，永远不知道跑了多久、用了几个工具、结束时是什么状态。

**落点**：`Note` 加 `startedAt` / `endedAt` / `tools`；在 `op()` 拿到终态时回写。`/status` 就能答"最近 10 条任务的中位耗时"。

**代价**：两个字段 + 一次 `put`。注意回写要在 DO 内做，别在查询路径上写（`/op` 会被轮询，每次都写就是每次一次 storage 写）。

**优先级：中。** 等有 100 条真实任务再看，现在看也看不出规律。

### 5. 抓到的网页留指纹，不只是留正文

**来源**：coil `logExec()`：输出超过 16KB 就截断，但截断处写上 `[truncated: {bytes} bytes, sha256 {hash}]`。

**我们现在的样子**：`fetch_url` 超长时直接 `slice`，模型看到的是"内容就这样"。

**落点**：被截断时在结尾补一行「原文 N 字，已给前 M 字，sha256 前 16 位」。原文不存（存了就要考虑清理），只存指纹和长度。

**代价**：五行。**收益**：模型能自己判断"我没读全"，而不是拿半篇去下结论——这直接对应我们"不丢事"的主张。

**优先级：中。**

## 三、上一轮我说错的那条

上一轮我建议「用 coil 的 compact 思路补上会话回收」。查完发现这个建议不成立，原因有两层：

1. **压缩不等于回收。** `Conversation.compact()` 做的事是"把老的轮次折成摘要、摘要之后保留最近 N 个 token"。原条目还在 `entries` 里，只是不进上下文。存储一点没少。
2. **pi 没有删除会话的接口。** `cloudflare/agents` 的 `NOTES.md` 最后一段「Not done yet」原文：

   > Session deletion. pi has no conversation delete.

   我们自己 README 里写的「要回收得自己按 `sessions.list()` 清」也不准确——`sessions.list()` 只有列，没有删。

所以「会话只增不减」这个问题，在 pi 这一层是**无解**的。只剩三条路：

- **减少会话数**：让多条任务共用一个会话，用 `session.reset(handoff)` 划界。注意这只让 `sessions` 增长变慢，**entries 照增**，所以总存储几乎不变，收益比看起来小得多。
- **接受它**：一条任务几 KB，5GB 装十万条，一个人用一百年。我们 README 里这个估算是对的。
- **自己删表**：直接动 pi 的 SQLite 表，破坏它的一致性假设。不做。

**结论：这条不用做，也不该做。** 之前那句"唯一会随时间变坏的地方"说过头了，真正的答案是"它不会变坏到影响使用"。

## 四、想清楚了，这次不做

| 能力 | 为什么先不做 |
|---|---|
| `session.reset(handoff)` 做跨任务连贯 | 路径是现成的（`PiSession.reset(handoff?)`），但它会动摇 ADR 006「一任务一会话」。等真的出现"问你上一条"的需求再做，那时它是一天的活，不是一周 |
| `session.watch()` 做流式 | 官方笔记自己说了它没有 cursor、不能从任意位置重放。我们现在的「轮询 `/op`」语义更强：断线重连看到的是最终状态，不是补一段流 |
| `steer()` 边跑边追加指令 | 前端要配合，且一任务一会话下没有真实场景 |
| `executionMode: "sequential"` | 只有一个工具，无所谓。**记一笔**：pi 默认一轮内并行跑工具，将来加第二个工具如果有先后依赖，必须显式标 |

## 七、做的时候又冒出来的两件事

写凭据脚本时跑出来的，都不是原来清单上的：

**1. `/op` 在 `live` 分支不返回 `session`。** 终态返回 `{operationId, session, status, text}`，跑着的时候只返回 `{operationId, status, live}`。于是调用方在任务运行期间拿不到"它落在哪条时间线上"——而这个信息提交回执里本来就有。已改成两个分支字段一致。

**2. `maxChars` 被静默钳到 1000。** 模型要 400，工具给 1000，返回里一个字没说。它会拿"1000"这个数字去推断自己读了多少——那是错的推断。已改成：下限写进参数描述，参数被改写时在返回里明说。

**还没修的：正文开头是导航垃圾。** Cloudflare 文档的前 1000 字符是 `Skip to content / Docs / Search / Log in`。`htmlToText` 已经去掉 `nav/footer/aside/head`，但这些在 `header` 和一个 skip-link 里。这一条没动，因为它要改清洗规则，得单独验一批站点——不能顺手动，顺手改清洗是最容易把好站点也弄坏的操作。

## 附：这次查证到的、值得写进注释的三件事

1. **pi 默认开压缩**：`DEFAULT_COMPACTION_POLICY = { enabled: true, reserveTokens: 16384, keepRecentTokens: 20000, backgroundTokens: 32768 }`。我们没配，正好。
2. **一轮内工具有可能并行**：`ToolRegistration.executionMode`，默认跟随 settings。加第二个工具前先想清楚依赖。
3. **`conversation.abort()` 要等到整条会话 idle 才 resolve**：所以任何不响应 `abortSignal` 的工具都会把它卡住。见第二节第 1 条。
