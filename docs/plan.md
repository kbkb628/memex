# 开发模块与计划

写于 2026-11-09。这份文档回答两个问题：**代码该切成哪几块**、**按什么顺序动**。
它不回答「要不要做某个功能」——那由每个阶段开头的「要回答的问题」决定，答不上来就不做。

三个前提，变了就要重排：

1. **定位**：A 型（fork 自部署）+ 作品集。不是 SaaS，不做多租户。
2. **判据**：一条改动值不值得做，看它解决的那个问题在我们这里存不存在（ADR 015）。不看好不好。
3. **加字段前先回答「谁读它」**（ADR 015），答不出来就不加。

---

## 一、模块划分

按能力域切，不按文件切。切法只有一个标准：每个模块要有明确的**输入、输出、读者**。

| 模块 | 负责的问题 | 现在在哪 | 谁读它的输出 | 状态 |
|---|---|---|---|---|
| **M1 触发** 谁让它醒 | 什么时候该动 | lifecycle jobs（`patrol` 每天 / `ingest` 3 小时），常量写死 | `/routines` → 页面「它自己会醒」 | 有，但不可配 |
| **M2 摄取** 看什么 | 从哪拿材料 | `feeds.ts`：5 个源、`fetchFeed` 重试一次、预算闸门 | M3 判定 | 稳，ADR 014 刚换完 |
| **M3 判定** 值不值得 | 这条该不该进收件箱 | `prefilter`（词表，未默认启用）+ 模型 + `want` | 收件箱 / 跳过区 | **口径未定**，见 P0 |
| **M4 目标** 推进什么 | 做完没有 | `goal.ts`：criteria / digest / judge / decide；`MAX_ROUNDS=6` | 页面目标一节、`/goals` | 稳，比三个范本都严 |
| **M5 存储** 记住什么 | 下次还要用什么 | DO SQLite：`inbox:*`、`goal:*`、`patrol:last`、`ingest:last` | 页面、`/status` | **只留最后一次**，见 P1 |
| **M6 呈现** 谁能看见 | 它在干什么 | `public/index.html` 667 行 + 22 条线上断言 | 用户 | 有，缺「依据」 |
| **M7 行动** 能做什么 | 除了看还能干嘛 | `tools.ts`：只有 `fetch_url`，只读（ADR 003/008） | 模型 | **一个工具**，见 P4 |

一句话读法：**M1→M2→M3 是输入端，M4 是目标端，M5 是记忆，M6 是脸，M7 是手。**
现在的短板不在手（M7，太远），在 M3 的口径和 M5 的留存。

## 二、阶段与顺序

排序依据不是「哪个功能更想要」，是**哪个问题现在有数据但解释不了**。

| 阶段 | 要回答的问题 | 主要动的模块 | 前置 | 量级 |
|---|---|---|---|---|
| **P0 定口径** | 一条被跳过的东西，是源不对、want 不对，还是判定太严？ | M3、M6 | 无 | 1–1.5 天 |
| **P1 补留存** | 三天前那条为什么判过？现在查不到。 | M5、M4、M6 | P0（理由要结构化才存得下） | 1–2 天 |
| **P2 让它可配** | 改个巡检间隔要改代码重新部署，合理吗？ | M1、M2、M5 | P1（配置变更要留痕） | 2 天 |
| **P3 出口** | 卡住之后呢？ | M1、M6 | 触发条件：`stuck` 连续两次非空 | 1 天 |
| **P4 行动** | 除了读一个网页，它还能做什么？ | M7 | 需先定副作用授权模型 | 只定边界 |

**P2 之后必须停一轮。** 不是休息，是「验证窗」规则：任何影响判定的改动，上线后至少攒够 5 条新判定再评价好坏。换源那次就是靠这个规则才发现杠杆在源不在词表。

## 三、P0 定口径（先做这个）

**为什么是它**：换源后 24 小时判了 3 条，1 进 2 跳。其中 GLM-5.2 那条被判 SKIP，理由是「你明确不要的榜单和生态影响叙事正是主体」——判定准确执行了 `want`，但 `want` 本身写窄了。**现在这套系统能证明自己遵守了口径，不能证明口径是对的。**

三件事都必须做，缺一件回放就没有意义：

### P0.1 `want` 从一句话变成两栏 · 已落地 2026-11-09（ADR 017）

现状：`want: "我关心 Durable Objects 的新用法"`，一个字符串，正反混在一起。

改成：

```ts
type Want = string | { want: string; avoid?: string };
```

单字符串继续合法（5 个源的旧数据不用迁）。页面上把 `avoid` 单独显示——**「不要什么」是判定理由最常引用的那一半，现在它藏在模型的解释里。**

- 验收：`feed-check.mjs` 加断言——两种形态都能解析；`avoid` 会进提示词且位置在 `want` 之后。
- 失败怎么办：如果模型开始把 `avoid` 当硬过滤（能沾边就跳过），说明它被写成了否决权。改成「`avoid` 是降权，不是门槛」，在提示词里写死。

### P0.2 判定结果结构化 · 已落地 2026-11-10（ADR 018，第二版）

现状：`note` 是一段自由文本，存得下人话，存不下机器要用的东西。

```ts
type Verdict = {
  keep: boolean;
  why: string;          // 人话，一句话
  readChars: number;    // 正文读到了多少字符；0 = 只有标题
  readOk: boolean;      // 抓正文成功了没有
};
```

`readChars` 是这一条里最关键的数：**「它读了 11k 字才判」和「它只看见标题就判」在页面上现在长得一样**，而后者才是判错的来源。

- 验收：`/inbox?all=1` 每条带 `readChars` / `readOk`；页面跳过区显示「读了 N 字 / 只看到标题」。
- 失败怎么办：如果 `readOk=false` 的比例超过三成，说明问题不在判定而在抓取（M2），P0 先停下修抓取。

### P0.3 `replay.mjs`：不花钱的回放台 · 已建成 2026-11-10

拿一批 `(title, summary, want)` 直接跑判定，输出矩阵。样本来源两个：线上已存的判定记录、手工构造的对照片（像 `inject-probe.mjs` 那样）。

用途只有一个：**改 `want` 之前先在这上面看结果变了没有**，而不是改完等三天。

- 验收：能跑 10+ 条，输出「旧 want / 新 want」两列判定，差异行高亮。
- 不进 CI（结论随模型版本变），但**要能重复跑**。

### P0.4 用回放定 `want`，再上线 · 口径已定（C），待部署

- 交付：5 个源的 `want` 各改一版，回放对比，把结论写进 ADR 017。
- 这里需要你拍板的一件事：「模型能力分水岭」（首个能当通用编码 agent 的开源权重模型）算不算「生态影响叙事」。**这是产品判断，我不替你定**，我只给回放数据。
- 阶段完成标志：`replay.mjs` 上，旧 `want` 判 SKIP、新 `want` 判 KEEP 的那类条目，你逐条认可。

**明确不做**：不加源、不换模型、不动 prefilter 词表。P0 只回答「口径对不对」，任何同时改口径和改输入的实验都得不出结论。

## 四、P1 补留存

**为什么**：现在 `rounds` 用 `.slice(-3)`，`MAX_ROUNDS=6`，跑到第 4 轮就丢第 1 轮；`patrol:last` 每次覆盖。丢的恰好是「为什么没做到」那部分。

### P1.1 `rounds` 只追加
去掉 `slice(-3)`，改成保留全部轮次 + 单条答案长度上限（超长截断并标记 `truncated`）。
- 验收：`goal-check.mjs` 加断言——6 轮全在；截断标记存在。
- 边界：不引入分页。6 条之内页面直接铺开。

### P1.2 判定留输入指纹
每条判定存 `sha256(title + summary)` 前 16 位 + `readChars`。
- 理由：`answer_contains` 的教训是「判定结果不能自证」。有了指纹，才能回答「这条和昨天那条是不是同一件事」——也是 P0.3 回放要去重的依据。
- 验收：同一条被重复抓到，指纹相同，`/inbox` 能标出来。

### P1.3 一次巡检 / 一个目标结束时的「收尾页」
不是日志，是一页能读懂的东西：目标、每轮答案、每轮判定、谁确认的、花了多少。
- 格式抄 Batty 的 retro（markdown），不建表——**它的读者是人，不是程序**。
- 验收：`GET /goals?id=x` 能返回这一页的 markdown；页面上「已结束」的目标点得开。

### P1.4 保留策略
按天归档，90 天后删。**这条要等 P1.3 有人真的翻过才做**，否则是给假想读者写清理逻辑。

## 五、P2 让它可配

现在改巡检间隔 = 改 `home.ts` 里的常量 + 重新部署。Pots 的 `routine add` 证明这件事可以是一条数据。

### P2.1 routine 表
`{ id, label, everyMs, enabled, last: { at, ok, summary } }` 存 DO。两条内置（`patrol` / `ingest`），页面能改间隔和开关。
- 约束：改间隔立即重排 `lifecycle` job，不等到下个周期。
- 验收：`/routines` 的 `next` 在改完之后 1 秒内变；`live-check` 现有 3 条断言不退化。

### P2.2 源可暂停
`feeds` 加 `enabled`。**不删是重点**：删了会连带清掉已判定的记录（上一轮本地删 HN 首页清了 31 条），暂停不会。

### P2.3 配置变更留痕
谁改的、什么时候、旧值是什么。**这是 P2 的前置而不是附赠**——一个能改自己节奏的系统，没有变更记录就没法回答「它为什么昨天没跑」。

## 六、P3 出口（等触发）

**触发条件不变**：`stuck` 连续两次非空。从上线到现在一直是空的，给没出现过的问题写代码只会带来新问题（什么时候放弃、放弃算不算丢）。

真到了那天，做的是三件小事，按顺序：

1. **分类** `stuck`：抓取失败 / 模型失败 / 判定失败。三类该给人看的东西不一样。
2. **升级给人**，不自动重试（抄 Batty）。自动重试通常只是再卡一次。
3. **定义「放弃」**：`cancel` 是人的决定，`failed` 是系统的结论。现在 `endedWhy` 里这两个词混着用，届时必须分开。

## 七、P4 行动（只定边界）

现在只有一个只读的 `fetch_url`（ADR 003/008）。往「能做事」跨之前，必须先回答三个问题，答不上来就一直只读：

1. **授权粒度**：一次授权管一次动作，还是管一类动作？现在 `operationId` 幂等只保证不重复执行，不保证「该不该执行」。
2. **失败可逆吗**：读网页失败可以重试，发消息失败不能重发（会重复打扰人）。
3. **谁来确认**：`human` 条件已经证明「等人确认」这条路能停在 `waiting` 而不是判失败——写操作应该复用这个，而不是新造一套审批。

顺序上先扩**只读**工具（读仓库、读具体条目），把 M7 的接口形状磨出来，再谈写。

## 八、验收怎么自动化

现有四道自检 + 一道线上，每阶段的增量断言：

| 阶段 | 新增/变更的断言 | 现有基线 |
|---|---|---|
| P0 | `feed-check` +2（want 两形态）、`page-check` 覆盖新区块 | feed 9/9 · page 31/31 |
| P1 | `goal-check` +2（6 轮全在、截断标记） | goal 37/37 |
| P2 | `live-check` +1（改间隔后 next 立刻变） | live 22/22 |
| P3 | 无（触发前不写） | — |

规则：**每个阶段的断言必须先红一次**（故意改坏），否则不算数。`page-check` 那次就是这么验的（27/28）。

## 九、什么时候该推翻这份计划

出现下面任意一条，说明排序错了，停下来重排：

1. **P0 跑完还是判不出好坏**（回放里新旧 want 判定全一致）→ 说明瓶颈不在口径，在源；回 ADR 014 那条路。
2. **连续三天零条目** → 不是判定问题，是覆盖问题，P1/P2 全部让位。
3. **`stuck` 突然持续非空** → P3 提前，其余暂停。
4. **你自己三天没打开过这个页面** → 那它是作品集，不是日用品。计划重心整个换：先做「一眼看懂它在干什么」，而不是判断质量。

第 4 条最该认真对待。它决定后面所有取舍。
