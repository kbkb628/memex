# 019 · 源不是坏了，是化石了

**日期**：2026-11-10
**状态**：已换（hnrss → HN 搜索接口，阈值与关键词同时调整）

## 事情是怎么被发现的

不是靠读代码，是靠一个数字不对：线上 `/routines` 里 `ingest.last` 是
`fresh: 0, submitted: 0`，连着好几轮。而页面上那一节写的是「每 3 小时一次，下次在几小时后」——**看起来一切正常**。

顺着查下去，本机打三个 hnrss 订阅全是 502，从 11:24 到 18:04 一直没好。
一开始当成「这台机器的网络问题」，因为这台机器到 Cloudflare 整条线路不通，是老毛病了。
所以新加了一条线上断言：把 `ingest.last` 的 feeds / fresh / submitted 和每个坏源的原因打出来。

线上跑完，答案是：**worker 打过去也是 502，一模一样三个。**

于是可以确定两件事：
1. `fresh: 0` 的原因不是「今天没内容」，是「三个源全废了」，而页面上没有任何东西能区分这两者。
2. hnrss 只是别人架在 HN 搜索接口上的一层 RSS 包装，多一跳就多一个会坏的地方。

## 换的时候顺手量出一个更难看的东西

换地址本来只该是「同一批内容换个门口」。但测试查询时发现：加引号的短语查询
`"llm agent"` 精度极高，**最近一条命中停在 9 个月前**。

原因很直白：标题要一字不差含这个短语，**并且**攒到 20 分，两个条件同时成立太罕见。
按「标题命中 + 20 分以上 + 最近 7 天」量三个源：

| 关键词 | 7 天 | 30 天 |
|---|---|---|
| durable objects | 0 | 0 |
| agent runtime | 0 | 1 |
| llm agent | 1 | — |

**三个源加起来一周一条。** 产品没有输入端，判定层做得再准也没意义。

ADR 014 当时量的是「准不准」（19 条几乎全对题），没量「一周能给几条」。
这两个数不是一回事，而第二个才是可用的前提。**一个再准、但半年没有新内容的源，对「发现」这件事等于零。**

## 决定

**1. 从 RSS 改成直接吃 JSON。** `fetchFeed` 按 `content-type` 分派（不按域名），
JSON 走 `parseHnSearch`。顺手多了分数和评论数，它们进摘要 —— 原来 hnrss 只给标题和链接，
模型只能靠标题猜，猜不准就报「材料不足」。

**2. 去掉 `points>20`。** 分数在这里不代表质量，只代表发得早晚：1 分 0 评那批标题里就有
「升级 agent 踩了什么坑」「用 SQLite 替掉回合式 agent」，而 20 分那条只是发得早。
判值本来就是模型的活，用一个粗糙代理把它挡在外面，等于用一个更笨的过滤器换钱。

**3. `durable objects` 换成 `cloudflare workers`。** 不是嫌它不准，是它真没量：
标题命中 30 天内 0 条，门槛降到 0 分还是 0。同一个运行时话题换个词一周 3 条。
留一个永远空转的源，等于在页面上摆一个「一切正常」的假象。

释放后的进量（最近 7 天，标题命中，不限分数）：cloudflare workers 3、agent runtime 6、llm agent 14。

**4. 身份改用 label 匹配。** 换地址时 url 正是变的那一侧，`--add-defaults` 按 url 判「有没有」，
会把新地址当新源加进来、旧的留着，于是 `failed[]` 里永远挂着三条坏源，
「有源在坏」这个信号从此不再有信息量。`--migrate` 按 label 找同一个源，显式删旧的再建新的。

## 代价

- **基线重建**：换地址 = 新 id = 一轮只记基线、一条都不提交。旧的判定记录连带清掉（这次清了 3 条）。
- **噪音回来了**：1 分 0 评的 Show HN 会被喂给模型。这是有意的 —— 它正是 `avoid` 里
  「通篇只有主张而没有任何可核对内容的发布稿」要挡的东西，也是这个产品唯一值得展示的能力。
- **hnrss 的兜底没了**：现在只有一个上游。但它本来就是二层，一层挂了另一层也没保住。

## 什么会推翻这个决定

- 一周之后 `skipped` 占比超过 90%，说明模型在做无用功，该把分数门槛加回来（哪怕只加回 5 分）。
- `fresh` 依然长期为 0，说明关键词还是太窄，该换题目而不是换阈值。
- HN 搜索接口开始限流（它没有文档化的免费额度承诺），届时要么加缓存要么换源。

## 方法论，两条

1. **量一个源，要同时量「准不准」和「一周几条」。** 只量前者，会得到一批精挑细选的化石。
2. **「定时器在转」不是「它抓到了东西」。** 这两件事在页面上长得一样，直到你把
   `ingest.last` 里的 feeds / failed / fresh 摆出来。现在的 live-check 每次都会打这三样。
