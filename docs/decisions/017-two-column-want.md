# 017 · 关注点拆成两栏，且「不要的」只是降权

**日期**：2026-11-09
**状态**：结构已落地（P0.1），口径未动（P0.4）

## 问题

`want` 一直是一个字符串：

> 有人真的用它做了东西、或者踩了坑的具体记录：自托管实现、状态与恢复的真实问题、成本事故、迁移复盘。**不要**融资、招聘、发布公告、纯观点。

一句话里同时装了两个东西：**什么算值得看**，和**什么不算**。看起来省事，代价在出结果的时候才显出来。

一条被判 SKIP 的记录是这样的：

> 你明确不要的「榜单」和「生态影响叙事」正是主体

这句话没法回答「它是因为命中 `want` 才留、还是因为没踩 `avoid` 才留」。而这两种错误要改的地方完全不同：前者是源选错了，后者是口径写窄了。**在一个句子里，你分不清是哪一种。**

这就是 P0 的第一步：不改内容，只把句子切成两栏。切完之后，「因为踩了不要的」这条理由才有地方可指。

## 决定

```ts
type Brief = { about: string; avoid?: string };
type FeedWant = string | Brief;
```

三个具体决定：

**一、`avoid` 是降权，不是门槛。** 这条写进了提示词：「两栏冲突时以『我要的』为准」。理由是不对称的——把 `avoid` 当硬过滤，收件箱会静悄悄地变窄，而用户不知道自己错过了什么；把它当降权，最坏是多进来一条无关的，用户一眼就能扫掉。**这是这个结构唯一容易被用错的地方**，所以它不只写在文档里，也写进了每次调用都会带的那几行。

**二、判 SKIP 时要引出踩中的那一条。** 「因为踩了『我不要的』」如果只写这半句，理由仍然无法核对——它可能引了 A 却踩的是 B。要求原样引出来，等于给「降权」这个模糊的东西留一个可核对的锚点。

**三、形状跟着内容走，不跟着类型走。** 没填 `avoid` 的源在存储里仍然是一个字符串，不强制升级成对象。线上已有 5 个源，如果这里要求统一迁移，部署那一刻写错一个字段它们就全变成空 `want`——**而空 `want` 不会报错，只会让它对所有内容都说「无关」**。`readWant` 两种形态都认，老数据不动也能跑。

## 没做的

- **没改任何一条 `want` 的内容。** 五个默认源只是把原句从「不要」处切开，语义完全等价。P0.4 才动内容，因为回放需要一个干净对照：先证明「只改结构」不改变判定，之后的变化才能归给口径。
- **没在页面上展示已有源的两栏。** 页面现在根本没有源列表（那是 P2 的事），只加了一个 `avoid` 输入框，让「不要什么」至少有地方填。
- **没验证模型是否真的会引用 `avoid`。** 结构检查只能证明它出现在提示词里、位置对。是否照做要靠 P0.3 的回放台和真实数据，现在下结论就是猜。
- **没部署。** 线上源的 `want` 还是旧的单栏字符串，新代码读出来是「我要的：<原句，含不要>」，行为与现在等价。等 P0.4 定完口径一起上，少一次部署窗口。
