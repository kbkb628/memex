删掉记忆层（331 行）、五层提示词（141 行）、会话分叉路由（约 100 行）、memex 界面（1044 行），

## 为什么

上一版的每一层单独看都站得住：记忆分四态是防止模型把自己上一轮的猜测当事实；提示词分层是因为长期人格和临时任务要求混在一起会互相污染；会话分叉是为了让长活不阻塞入口。

但它们同时存在时，**没有任何一条能被验证**。你没法回答「这个 agent 现在到底会不会丢事」——因为要跑通一次完整的检查，得穿过四套机制，而其中任何一套的小问题都会伪装成别的问题。

一件东西在还不能证明自己最核心那句话的时候，加层不是在增强它，是在给它的失败制造掩护。

核心那句话是：

> 发一条消息，页面可以立刻关掉，它做完了答案还在等你。

这一条不成立的话，记忆准不准、提示词分不分层、能不能分叉，全都不重要。

## 放弃了什么

**放弃「一眼看上去很完整」。** 现在的版本只有一个文本框和一个结果列表，看起来像三小时的作品。这是故意的：界面在第五步才回来，前四步用丑的，因为好看的界面会让人误以为功能已经齐了。

**放弃「已经把记忆问题解决了」这个说法。** 记忆层是这套东西里最容易讲故事的部位，也最容易被 Mem0 / Hermes 这类项目比下去。它现在的准确位置是：一个已知的做法，等有了需要记住的东西再装回来。

**放弃了 fork 出去的执行会话。** 它解决的是「长活不阻塞入口」，但现在连一个长活都还没有。真正的需要出现时再装，那时才知道要 fork 什么、fork 几次。

## 什么情况下应该反悔

- 当第五步（界面）之前，你连续三次想「这里要是能记住就好了」——那时装回记忆层，不是为了架构好看。
- 当同一句提示词在不同场合确实该有不同说法，且你已经手工改过两次——那时加第二层。
- 当一次任务的耗时超过一次 HTTP 请求能等的范围，且它需要并行试两种做法——那时 fork 才有对象。

反悔的门槛是「已经发生过三次」，不是「将来可能需要」。

## 保留了什么

三样东西没动，因为它们是这套东西的地基，不是装饰：

1. **模型层与部署平台解耦**（`models.ts`）。之前焊在 Workers AI binding 上，导致 `wrangler dev` 必须走 remote 模式，本地一行都跑不起来。这个坑不值得踩第二遍。
2. **回执优先**。`/submit` 先落盘再返回，模型还没开始跑。这不是性能优化，是整个项目的主张所在。
3. **先查 pending 再 wait**。任务还在跑的时候去 wait，会把一个 HTTP 请求挂在对象里等几十分钟，白白占着这个单线程的对象。
