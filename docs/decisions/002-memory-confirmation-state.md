# 002 · 记忆分状态，只有人能把它升级为「已确认」

- 状态：已采纳
- 日期：2026-11-03
- 影响范围：记忆层、UI、以及模型能看到的一切上下文

这是这个仓库存在的理由。其他决策都可以换，这一条不行。

## 背景

现在的 agent 记忆基本都是「模型自己维护的持久事实列表」。它读对话，判断什么值得记，调用 `save_memory` 写进去，下一轮再读回来。

这套做法很顺滑，但它有一个结构性缺陷：**记忆里存的是模型的自述，不是有证据的证词。**

出事的路径固定得像剧本：

1. 模型根据若干线索推断出「用户倾向于做 X」
2. 它把这个推断写进记忆
3. 下一轮，它读回这条记忆。此时这条记忆的形态和「用户说过的话」完全一样
4. 它把 X 当成既定前提，继续往下推
5. 三步之后，结论已经离事实很远了，而且每一步都「有依据」

问题不在某一次推断错了，在于**推断和事实在存储层面长得一模一样**，读回来就分不清了。

## 为什么 prompt 挡不住

最直觉的修法是在系统提示里写「不要把推断写成事实」。

这不管用，而且失败方式很隐蔽：模型会真诚地认为自己没有违反规则——「我确实是根据用户的表述总结的」。它不是在撒谎，它是在自我说服。语言模型对自己上一轮的输出有天然的信任，这是它的工作方式，不是它的品行问题。

凡是需要模型**持续自我约束**才能守住的规则，都会在长对话、上下文压缩、或者一次含糊的表述之后失效。要守住，只能让它守不住——把约束挪到代码里。

## 决定

记忆有两个正交的维度：

**状态（status）**

- `discussing` —— 还没定论
- `confirmed` —— 已确认
- `rejected` —— 明确否决（保留，不删除）

**裁决人（decided_by）**

- `null` —— 还没人裁决
- `model` —— 模型声称有依据
- `user` —— 本人点过确认或否决

写入时：

- 带 `quote`（用户原话逐字引用）→ `confirmed` + `decided_by = "model"`
- 不带 `quote` → `discussing` + `decided_by = null`

**关键点：带 quote 也不等于已确认。** 它只等于「模型声称它有你的原话」，状态是「待你复核」。

只有人在界面上点「确实如此」，`decided_by` 才变成 `user`。只有这个状态叫「本人核过」。

模型检索记忆时，看到的是四种不同的标记：

```
[已确认·本人核过]   ← 可以当日事实用
[已确认·模型声称]   ← 只是线索，不能当前提
[讨论中]           ← 可以被推翻
[已否决]            ← 留着，用来避免重复犯错
```

## 放弃了什么

**顺滑。** 主流的「模型自己攒记忆」方案，用户体验是无感的：你说着话，它自己就知道该记什么。这里不行——每条记忆都会在界面上等你点一下，不点就一直是讨论中。

这是刻意的摩擦。**摩擦的位置就在「什么算事实」这个决定上**，而这恰好是最不该省掉的一次确认。

**自动积累的规模。** 没有人工裁决，记忆可以无限增长；有裁决，增长受你注意力的限制。对一个个人 agent 来说，这不是坏事——记不住那么多，本来也说明那些东西不重要。

## 这套设计的真实边界

必须说清楚：**它不能阻止模型编造假引用。**

模型完全可以编一句像模像样的话当 `quote` 塞进来，状态照样是 `confirmed`。代码拦不住这个，因为代码没法判断一句话是不是真的被说过。

它提供的是**可审计性**，不是**不可伪造性**：

- 原话被单独存下来，随时能核
- 没核过的条目永远带着「模型声称」的标记，不会被当成事实
- 编造会留下痕迹，而不是溶进一份看起来权威的记忆里

差别在于：一个会说谎但每次都留底的系统，比一个真诚地记错、且错了也看不出来的系统，要可控得多。

## 什么时候该重新考虑

如果有一天能对引用做自动校验（比如消息来源本身带签名，或者有一个可信的对话原文存证），那 `decided_by = "model"` 这个中间态就可以去掉，直接信任。在那之前，这个中间态是必要的。

## 这个决定的来源

它来自一个很朴素的原则：**在 agent 越来越自主的时代，把「什么算事实」的最终判断权留在人手上。**

同一族的设计还有「代发消息前必须给人看预览」「多个可选路径时给选项而不是替人决定」。它们共享同一个立场——agent 可以提议，不可以裁定。
