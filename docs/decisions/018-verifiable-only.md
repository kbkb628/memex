# 018 · 口径选「只算可验证的」，以及一个证明不了它的回放台

**日期**：2026-11-10
**状态**：口径已定（P0.4 待上线）；回放台可用，但对当前源分辨力低

## 定下来的口径

用户在三个选项里选了 **C：只算可验证的**。

被问的那条内容是一条 HN 帖子，标题主张「GLM-5.2 是首个能当通用编码 agent 的开源权重模型」。旧口径判它 SKIP，理由写得很准：「你明确不要的『榜单』和『生态影响叙事』正是主体」。

问题不在执行，在口径：它把**能力边界的位移**和**生态影响的议论**打包成了同一类。前者是可证伪的工程事实（某类任务以前开源权重做不到，现在做得到，你能自己跑一遍验证），后者是不可证伪的叙事（AI 会不会取代谁）。两者的区别不在话题，在于**看完之后你能做什么决定**：前者会改你下周的代码，后者不会。

C 的写法是把判据从「话题」换成「证据形态」：

- 要：能力边界位移，**附可复现的 demo、代码或具体 benchmark 数字**
- 不要：只有结论没有证据的发布稿、榜单、取代论

这条已经写进 `scripts/briefs.json`。**还没上线** —— 等 P0.4 一起部署。

## 回放台：建成了，但证明了另一件事

`scripts/replay.mjs`：抓真实条目，用两版口径各判一次，摆出差异。不判断对错，机器没有立场。

在固定样本（`scripts/samples/HN-llm-agent.json`，5 条）上跑了四轮，最终结果是：

> **旧口径留下 1 条，新口径留下 1 条，判定翻转 0 条。**

C 在这批样本上没有改变任何判定。原因不是 C 没用，是**这批样本根本没有机会体现它**：

> 5 条里跳过 4 条，而这 4 条的理由**没有一条提到 `avoid`** —— 全是「材料不足」。hnrss 的关键词订阅只给标题、链接和分数，**没有正文**。回放台也不读正文（省时间省钱）。

所以回放台对当前源的分辨力很低：它只能测「摘要层面的口径差异」，而当前源几乎全是摘要不足。**要验证 C，只能在线上跑** —— 线上模型可以 `fetch_url` 读原文。这是 P0.4 上线后观察窗的事。

### 三个方法论教训

**一、样本必须固定。** 第一版每轮现抓，连跑三次，同一版口径的「留下」条数是 3 / 2 / 0。看起来像口径不稳，实际是 HN 每几小时换一批帖子——比较的是三组不同的题。现在默认读 `scripts/samples/*.json`，`--refresh --save` 才换。

**二、只喂摘要这件事必须在输出里写明。** 否则「回放结论」会被当成「线上判定的复现」，而两者的输入根本不一样。

**三、回放台测不出「材料不足」以外的毛病。** 它测的是口径，不是判定质量。判定质量要看线上的 `givenChars` 和 `cited`。

## 第一版判定结构化做错了，这是改回来的

P0.2 最初的设计：提示词要求模型写 `因为：<原样引出的那一条>`，服务端核对它是不是 `avoid` 的子串；核不上就记 `hitOk: false`。

跑三轮，全部失败：

1. 模型把「材料不足」写进「因为」行 —— 那根本不是 `avoid` 里的东西；
2. 加强措辞后，它把整句解释连同括号注释都塞进去；
3. 同一段提示词，旧口径那边连写三次「因为：材料不足」，核不上三处。

**结论不是「措辞还不够狠」，是设计错了**：它让模型来提供可核对的东西，而模型本来就不擅长守格式，尤其在它认为理由显而易见的时候。

改成反过来：**不让模型标注，由服务端去它的话里找。** 判 SKIP 之后，拿 `avoid` 拆出的每一条去理由里搜，找到就记下。找到的那条必然真的出现在 `avoid` 里，所以不存在「核对不上」；剩下的唯一问题是「它有没有具体引用」，而那正是要的指标。

字段也跟着换：`hit` / `hitOk` → `cited: string[]`。

拆 `avoid` 有两个必须注意的地方，都是测出来的：

- **先剥括号再切分。** 反过来会把 `发布稿（摘要短、看不到正文不算这一条）` 从括号内的顿号处切开，得到两个都不是词的东西。
- **一两个字的条目不参与搜索**（`等`、`啊`），否则会命中一切。

## 顺带修的两个真问题

**材料不足被写成了「没有证据」。** 新口径引入 `avoid: 只有结论没有证据的发布稿` 之后，模型开始把「摘要太短，看不清」也归到这一条 —— 一个口径副作用。提示词里补了一条：材料不足时结论照旧 SKIP，但理由老实写「材料不足」，不要往上靠。

第一次写成了「材料不足不等于内容不行」，结果它开始**在材料不足时猜着留下**（回放里新口径一下从 1 条变成 4 条）。第二版改成「结论照旧 SKIP，只改理由归属」，才回到 1/1。

这条值得单独记：**一句「不要误判」的提示词，最省事的实现方式是让它往宽了判**，而那正好是另一种错误。

**判定结果不再只有一段话。** 每条 SKIP 现在带 `givenChars`（我们给了多少材料，服务端确知）和 `cited`（理由里点到了哪几条 `avoid`）。页面上显示成「材料 146 字」「提到「榜单」」。旧记录没有这两个字段，回落到 `note`，不崩。
