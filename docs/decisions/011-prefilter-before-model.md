# 011 · 粗筛放在模型之前，因为它错不起

**日期**：2026-11-06
**状态**：已落地

## 问题

今天的额度在下午就满了：自动判断用掉 20/20，而收件箱里 14 条判断有 10 条是「跳过」。

跳过的内容本身没问题——模型给的理由都很实在（「NVKE 是 GPU 集群运维层，不沾 agent 运行时」「MoofTCP 是 68k Mac 协议栈」）。问题在于这些判断**本来不需要问模型**：HN 首页是「所有技术话题」的首页，不是「agent 话题」的首页，一天二十条里有一大半命中率天然为零。

结果是两件事同时发生：额度被噪音吃光，而额度一光它当天就不再干活。用户看到的不是「额度用完了」，是「它停了」。

## 决策

给源加一个可选的 `prefilter` 词表。抓取后、提交前，先拿标题 + 链接 + 摘要开头跑一遍：一个词都没命中的，直接记进 `seen`，不建任务、不占额度、不进收件箱，只在 ingest 报告里计数并给几条样本。

只有配了词表的源才筛。默认只给 HN 首页配，因为只有它是泛话题源；Cloudflare 博客和阮一峰周刊本身就是筛过的，再筛只会误杀。

## 几个不显然的地方

**词表不能并进 `want`。** `want` 是给模型看的一句话判断标准，粗筛是「这种标题根本不用问」。混在一起会变成一句没法执行的提示词，而且调宽窄的时候分不清是哪一层在起作用。

**挡掉的条目不写收件箱。** 这不是判断结论，是规则结论——同样的标题加同样的词表，谁跑都是同一个结果，可以复算。模型判断不一样，不给理由就永远没法复盘。所以规则不进收件箱（那里每一条都该是「需要人看一眼的东西」），只给计数和样本。

**两个字母的词必须用词边界。** `ai` 用 `includes` 会命中 `said`、`main`、`explain`。改成 `(^|[^a-z0-9])ai([^a-z0-9]|$)` 之后，`-ai-`、`.ai/` 这类链接写法照样认得出，字母黏着的一个都不会误撞。中间试过「两字母只认标题」的特例，反而误杀了 `the-hackintosh-reborn-with-ai`，删掉特例更准。

**摘要靠不住，链接才是信号。** hnrss 的 `summary` 里只有「Article URL / Comments URL / Points」，一个字正文都没有。真正的线索在标题和链接里——`Inkling 2 Small` 这种标题完全没有关键词，全靠 `thinkingmachines.ai` 这个域名才捞回来。

## 代价

误杀是不可见的。模型挡错了，理由写在收件箱里，人一眼能看见；粗筛挡错了，那条内容根本不出现，没有人会发现自己错过了什么。

所以这个改动不能只靠「看着还行」验收。做法是拿**已有的模型判断当第二意见**回放：

```
node scripts/prefilter-check.mjs
```

它把已经判过的条目拉回来，只用标题和链接跑一遍粗筛，分成误杀 / 放行且有关 / 白放 / 正确挡掉四类。**误杀必须为 0**，有误杀就退出码 2，能拦住一次坏的词表改动。

两边代价本来就不对称：白放一条，多花一次调用，代价固定且可见；误杀一条，内容永久消失且无声。所以词表故意选得偏宽。

## 验收

回放（29 条已有判断，产物在 `receipts/prefilter.json`）：

```
误杀 0 · 放行且有关 9 · 白放 16 · 正确挡掉 6 · 不筛 2
配了词表的 31 条里，只需要喂 25 条给模型，省掉 19%。
```

**这个数比刚上线时的 40% 掉了。** 原因是样本变了，而且变得很有信息量：收件箱里堆了一批「含 `ai` / `claude` / `gemini` 字样、但模型判为无关」的条目 —— `Gemini Omni 1.2 Flash`、`Anthropic IPO buyers see valuation`、`A Jev that can ask Opus for help`。它们全都过了词表，然后照样白花一次调用。

也就是说：**词表的召回够，精度不够。** 它挡掉的是「完全不沾 AI」的那类（MoofTCP、MS Paint 漏洞、Kagi Search），挡不住「AI 领域的泛新闻」—— 而后者的量更大。

这个比例会随收件箱内容变化，重跑一次就是当天的真实值，不该当成固定指标。但下一版的方向已经很清楚了：光加词不管用，得加**否定词**（`IPO`、`hiring`、`valuation`、`Series X`），或者要求命中两个以上的词。都没做——先让它跑一段，看白放里到底哪一类最多。

真实一轮（HN 首页当天 11 条新的）：

```
fresh: 11   prefiltered: 9   submitted: 2   预算 20 → 22
```

11 条新的，只有 2 条花了调用，挡掉的 9 条零成本，且第二轮 `fresh: 0` —— 说明它们确实记进了 `seen`，不会被下一轮重新捡回来。

同一批上省 82%、累计样本上只省 19%，两个数都对：前者是那个时刻的 HN 首页，后者是攒下来的全部。**报数字时要说清是哪一种，不然听起来像在挑好看的。**

## 顺带做的一件事

`DAILY_CALLS` 从写死的 20 改成读部署变量，默认还是 20。不是为了让人调到无限——上限本身是这个东西的产品定义——而是因为「一天几件」因人而异，写死等于替所有人做了这个决定。改这个的直接动机是：验证上面那条链路需要绕过当天已用完的额度。

## 后来量了两件事，都否掉了「再加点词就行」（2026-11-07 追加）

**一、噪音不在链接里，在标题里。**

一度以为白放是链接 slug 撞出来的（`dsx-ai-factory` 把 NVKE 那条带进来的），于是把命中来源拆成标题 / 链接路径 / 域名三处分别量了一遍：

```
只在路径命中（无标题命中）   4 条 · 有关 2 · 无关 2
标题命中                   17 条 · 有关 5 · 无关 12
```

路径命中一共只有 4 条，而且一半还真的相关（`thinkingmachines.ai` 那条就是靠域名捞回来的）。**白放压倒性地来自标题命中** —— 所以「收紧链接匹配」这个方向是错的，改它会掉召回、不会提精度。

**二、`ai` 这个词现在是筛子的主要漏洞。**

HN 首页上大部分标题都含 AI，`ai` 一命中就放行，等于没筛。累计省 19% 不是词表写得不好，是**这个词在这类源上已经失去区分力**。再加否定词只能补几个明确的类别（IPO / hiring / valuation），补不动整体。

**三、真正的杠杆可能在源，不在词表。**

同样的关注点，换成 hnrss 的关键词订阅试了一下：

```
https://hnrss.org/newest?q="durable objects"&points=20  → 19 条
  Show HN: Durable Actors – OSS Durable Objects…
  Open Source Durable Objects for Postgres
  Celld: Self-hosted, distributed Durable Objects
  Why we're moving off Cloudflare Durable Objects
  Durable Object alarm loop: $34k in 8 days, zero users…
```

19 条几乎条条对题，而且都是「有人真的做了东西或踩了坑」。代价是量小 —— 这是全时段累计命中，不是一天的量。

所以这一层重新表述成一句话：**粗筛只能在源本身大致对题时才有意义**。泛话题源配宽词表，最好的结果也就是把「完全不相干」那一小类挡掉；想让它像样，得从源头换，或者同时要求命中两个词（这一条还没试）。

暂时**不动**：先让现在的配置跑一段，看白放里到底是哪一类最多，再决定是加否定词、还是把 HN 首页换成几组关键词订阅。**换源是产品决策，不该顺手做掉。**
